## 目标
将 `receiver/datadogrumreceiver/internal/converter/converter.go` 中现有的手写 `pcommon.Map` 属性写入统一收敛到 `AttributeBuilder`，使代码支持示例中的链式 `Set` 与批量 `SetAll`，同时不改变现有协议映射结果。

## 实施方案

### 1. 完善 AttributeBuilder
修改 `AttributeBuilder.Set` / `SetAll`：
- 保留链式调用和批量写入 API。
- 使用反射安全处理指针、命名类型和基础数值类型，支持 `model.VitalType` 等 string alias。
- 支持 `string`、布尔、全部有符号/无符号整数、浮点数及其指针；nil 指针跳过。
- 对 `[]string` 保留 OTLP slice 写入能力，避免丢失 `connectivity.interfaces` 和 `action.frustration.types`。
- 对 map/struct/slice 等复杂值继续通过显式 JSON 序列化写入，不让 `Set` 隐式改变既有 JSON 字段语义。
- 对空字符串沿用当前行为：不写入；数值 0 和 `false` 仍保留。
- 增加 AttributeBuilder 单元测试，覆盖链式调用、SetAll、指针/nil、别名类型、slice 和 unsupported complex values。

### 2. 将现有写入辅助函数改为 Builder 入口
保留特殊逻辑，但把底层写入改为 `AttributeBuilder`：
- `putString`、`putInt`、`putFloat`、`putBoolPtr`、`putIntPtr`、`putIntValue`、`putFloatPtr` 改为接收 `*AttributeBuilder`。
- `putStringSlice` 使用 builder 的 slice 支持。
- `putJSON` 先 marshal，再调用 `builder.Set`，确保 causes/CSP/debug IDs、page state、request/response、rect/sub_parts 等字段行为不变。
- `putSampleRate` 保留百分比到 0–1 的归一化和 clamp，再使用 builder 写入。
- 避免 helper 内部再次直接操作 `pcommon.Map`，除 AttributeBuilder 本身外集中管理属性写入。

### 3. 重构各事件转换函数
在每个 Span/Span Event/Resource 属性作用域创建一个 builder，并将属性写入改为链式或批量方式：
- `appendEvent`：公共 `event.type` / `rum.source`。
- `setResourceAttributes`：应用、服务、环境、Session、用户、SDK、采样率、OS、设备、网络、viewport 等。
- View：基础字段、计数、Vitals、performance、custom timings、JSON 结构字段。
- Action：Action、target、frustration、计数、position、`_dd.action` 和 view 关联字段。
- Resource：HTTP、resource、size、provider、Datadog trace/span、请求响应 JSON、status。
- Resource timing event：timing start/duration/end。
- Error：exception、CSP、causes、debug IDs、resource/provider。
- Long Task：长任务字段及用户示例中的 `Scripts` event 属性，优先使用链式 `Set`；可将同一 script 的固定字段组织为 `SetAll`。
- Vital：使用内置类型转为 builder 可处理的基础值，统一属性写入。
- Web Vital timing event：scalar 通过 builder，复杂 sub-parts/rect 继续先 JSON 化后 builder 写入。

### 4. 保持协议和输出兼容
- 不改变 Span name、kind、时间单位、status、事件时间单调性、resource 属性 key 和 raw JSON 行为。
- 不改变特殊字段的条件写入逻辑，例如空字符串、nil 指针、有效 HTTP status、非负 timing duration、sample rate 归一化。
- 不把复杂对象直接写成 Go 字符串表示，仍使用 JSON 编码。
- 不修改 receiver 路由、RecordTraces 输出或 exporter queue。

### 5. 测试与验证
- 更新/新增 converter 测试，验证重构前后关键属性值一致：View、Action、Resource、Error、LongTask、Vital、Resource timing 和 Resource attributes。
- 增加用户示例的 Long Task script 链式属性测试，以及 `SetAll` 等价行为测试。
- 运行 `gofmt`。
- 运行 `go test ./receiver/datadogrumreceiver/...`、相关 exporter/processor 测试、`go test ./...`、`go vet` 和 `git diff --check`。
