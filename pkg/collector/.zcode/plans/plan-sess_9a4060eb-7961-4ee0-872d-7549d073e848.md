## Goal
Optimize `InternalFields.MarshalJSON` so the `Additional` path no longer performs a full marshal → unmarshal → merge → marshal round trip, while preserving the current JSON contract.

## Implementation
1. Keep the existing fast path for `len(f.Additional) == 0` unchanged, so ordinary manually constructed `InternalFields` values continue to use `encoding/json`’s native struct/tag handling.
2. Replace only the `Additional` path with direct construction of `map[string]json.RawMessage`:
   - Allocate capacity for all known fields plus `Additional`.
   - Add each known field by calling `json.Marshal` on the field value and storing the result as `json.RawMessage`.
   - Apply the exact `omitempty` rules from `InternalFields` manually:
     - omit nil pointers (`FormatVersion`, `DocumentVersion`, `Drift`, the rate/pixel/bool pointers, `Configuration`, `ReplayStats`, `Action`, `Vital`);
     - omit empty strings (`TraceID`, `SpanID`, `SDKName`, `BrowserSDKVersion`, `RemoteConfigurationID`);
     - omit empty/nil `PageStates` and zero-length `DebugIDs`;
     - retain non-nil pointers even when their pointed value is zero or their nested struct marshals to `{}`, matching `encoding/json`.
   - Marshal known fields before applying `Additional`, so an invalid known field still returns an error even if `Additional` contains a colliding key, matching the current implementation.
   - Overlay `Additional` after known fields so valid additional values continue to take precedence on key collisions, including collisions with omitted known fields.
   - Marshal the final map once; this preserves validation and normalization of `Additional` `json.RawMessage` values and deterministic map-key ordering.
3. Add focused model tests covering the optimized path:
   - known fields with `omitempty` boundaries, including non-nil pointers to zero values and empty nested structs;
   - `DebugIDs` raw JSON behavior and invalid raw JSON errors;
   - `Additional` preservation, valid collision precedence, `null`/empty raw values, and invalid raw JSON errors.
   - Keep assertions semantic (`JSONEq`/decoded maps) rather than relying on object field order.
