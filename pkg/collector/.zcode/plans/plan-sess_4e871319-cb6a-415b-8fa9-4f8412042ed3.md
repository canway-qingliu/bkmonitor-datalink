目标：根据 `receiver/codereview.md` 优化 `receiver/datadogrumreceiver` 的可读性，保持现有行为、协议兼容性和对 pipeline → exporter 的不触碰。

实施范围与步骤：

1. **Handler 分层与命名统一**
   - 将 `Export` 中的 HTTP 请求处理流程整理为清晰的“请求上下文 → 解码 → 解析 → 构造 record → pre-check → publish → response”步骤。
   - 仅提取职责明确的小函数，统一 `rawEvents`、`bodySize`、`batch`、`record` 等语义化命名；合并重复的 bad-request 处理路径，但保留当前 metric、日志和 HTTP 状态码行为。
   - 为关键私有辅助函数补充简短注释，避免通过函数名仍需阅读实现才能理解。

2. **Decoder 可读性重构**
   - 把 `DecodeEvents` 的格式分派和各格式解析函数命名、职责整理清楚，保留 array、wrapped events、single object、NDJSON、JSON stream、gzip 和大小限制的现有行为。
   - 将 JSON token/EOF/object 判定相关辅助函数按“读取对象、读取数组、校验事件、限制累计大小”的职责分组；减少 `decodeObject` 内部局部状态和分支的阅读负担。
   - 将错误常量/限制器命名调整为表达错误语义的形式，保留 `errors.Is` 行为。

3. **Parser / Validator 结构整理**
   - 把 parser 的批量处理、单事件分派、公共字段解码、section 解码按职责分组；必要时将重复的事件构造逻辑抽成小型、命名明确的 helper。
   - 将 `Validator` 的通用校验与事件类型校验组织成统一的阅读顺序，保留当前“view/resource/error 原有 ID 规则、action/long_task 可无 ID、vital 当前规则”的行为。
   - 对 `rawEvent` 的字段常量和 section 常量做分组注释，说明它们分别对应公共字段和事件 section。

4. **Model / lifecycle 命名和注释**
   - 为配置快照、配置加载器、原始 payload、事件 marker、序列化 helper 等新增/修改的概念补充 Go 风格注释。
   - 不扩散重构 model 字段类型、不改变 JSON tag，不改变 receiver 的 config loader 注册和 reload 语义；只改善局部命名、函数顺序和注释。
   - 保持 `receiver` 通用配置 loader API 的语义清晰，必要时重命名内部 map/helper 以表达其用途，但不修改对外行为。

5. **测试和验证**
   - 先运行现有 RUM 测试作为基线，再做只影响可读性的修改。
   - 修改后执行 `gofmt`、`git diff --check`、`go test ./receiver/datadogrumreceiver/...`、`go test ./...` 和 `go test -race ./receiver/datadogrumreceiver/...`。
   - 对比 diff，确认没有修改 exporter、pipeline 或无关的已有工作树改动。
